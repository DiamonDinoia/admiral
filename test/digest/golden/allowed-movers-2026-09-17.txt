# Host class: ccmlin075 (Xeon w5-3435X, SPR), gcc 14.2.0, x86-64-v3 Release.
# Banked 2026-09-17 (91 ids at 37cd1c0); re-derived 2026-10-28 (the file name keeps the
# banking date; validate.sh and test/digest/README.md reference it).
#
# Every entry is a member of the address-allocation-layout class: the shipped arm's
# contract-reassociate codegen keys vector-arm dispatch on pointer alignment, so a
# runtime-allocator or scratch-layout change re-draws which address-sensitive cases move.
# The class pool is 1-D lengths with a prime factor > 11 (Bluestein/Rader arms, which
# change bits even with the col pin on), the lengths {96, 128, 160, 192, 256, 320} (the
# 1-D engine's output bits depend on data alignment there), and the N-D 32x32 and 96x96
# lines; single f32 lengths 55/56 ride along in the observed draws.
#
# Since 2026-10-28 the digest driver pins every transform buffer to one alignment class
# (test/digest/digest.cpp: mmap-page base + ADM_DIGEST_BUF_OFF=64), so driver-buffer
# alignment and allocation history can no longer move a case (measured: 0 movers across
# 10 runs and across pipe vs 1 MiB-file stdout sinks; the unpinned driver moved 3 under
# the same sink change). This list is the union of the two residual draws: the al16
# offset arm (ADM_DIGEST_BUF_OFF=16, 29 ids) and the banked binary run under glibc
# 2.43/libstdc++ 15 (admiral-ci-deb, 13 ids) = 32 ids, down from 108. It is an upper
# bound for environment variation on the unchanged tree only; a landing that changes the
# driver pin re-derives it with those two arms.
# The strict dialect is address-insensitive (0 movers in every experiment), so the

# fails the arm; ids that stop moving are an improvement (delete the entry, and the file
# when the class is fixed).
